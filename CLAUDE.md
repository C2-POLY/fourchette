# Fourchette

A Git client for macOS in Rust and egui: the history graph, branches, worktrees, stashes, an undo for every local action, a Claude assistant, the repository switcher and the GitHub project of the open repository. It began as a rebuild of another Git client, with a look closer to GitKraken.

## Project state

- `app/`: the application (the only code). `app/MECHANICS.md` and `app/mechanics.json` hold the values measured in the original app, with their evidence ids; keep them in sync when one of those values changes.
- `investigation.cany/`, `capture/`, `craft.json`, `attachments/`: what the rebuild tool found in the original app, kept on disk but ignored by Git. Read them, never edit them by hand. Never write the original app's name in the repository, commits, pull requests, issues or release notes: say "the original app".
- `ios/`: the companion for iPhone and iPad (#73), a SwiftUI app apart from the Mac one (iOS can't run `git`, `gh` or `claude`): it reads GitHub through its API with a token from the device flow, kept in the keychain, and its only write is moving a card on a project board. `project.yml` is its XcodeGen project (`xcodegen` from `ios/` writes the ignored `Companion.xcodeproj`), `Config.xcconfig` holds the OAuth App's client id (public, no secret), and `-sample` at launch shows invented repositories (`-sample -open board|pulls|history` with the sample project open there). It shows each repository's project board (a card moves by its menu, a swipe on iPhone or a drag on iPad), its pull requests with their checks, and its branches with their history. Build and test with `xcodebuild -project Companion.xcodeproj -scheme Companion -destination 'platform=iOS Simulator,name=<device>' test`.
- `site/`: the website, an Astro project published on GitHub Pages (<https://c2-poly.github.io/fourchette/>) by `.github/workflows/site.yml` on every push to `main` that touches it. English and French strings live in `site/src/i18n/`; its screenshots in `site/src/assets/shots/` come from the app's screenshot mode, in dark and light. Preview it with `npm install && npm run dev` from `site/`.
- Git ignores the tool's findings and working state (`investigation.cany/`, `capture/`, `craft.json`, `attachments/`, `feed.json`, `usage.json`, `build-activity.log`, `inbox/`, `pinned/`, `checks/`) and `app/target/`.

## Stack

Rust 2021 (rust-version 1.95, from rustup: Homebrew's `rust` is too old and has no x86_64 target for the release), eframe and egui 0.37 (the wgpu renderer on Metal, not glow, so a live resize stays clean), `rfd` for file dialogs, `serde_json`, `image`. Git, Claude Code and GitHub are reached through their command lines (`git`, `claude`, `gh`), never through a library or a token kept by the app. One exception: the update check reads the public releases API and downloads the .dmg with `curl` (no `gh`, which is optional for people who use the app, and no token).

## Commands

Run them from `app/`, with the Rust of rustup (with `brew install rustup`, put `$(brew --prefix rustup)/bin` first in PATH; Homebrew's `rust` is too old).

```bash
# Build and run on a repository (no argument: the current folder if it is a repository, else the tabs of the last quit, else the home page)
cargo run -- /path/to/repo

# Unit tests (fast, offline)
cargo test

# Live and slow tests: they call Claude Code and GitHub for real, and install an update from a disk image made on the spot
cargo test -- --ignored --nocapture

# Lints: no warning at all, so any new one stands out
cargo clippy

# Screenshot of the sample project (run from a folder that is not a repository, such as /tmp)
(cd /tmp && <app>/target/debug/fourchette --screenshot <out.png>)
```

Release (macOS), from `app/`:

```bash
# Build the universal .app and .dmg into target/release-bundle/
scripts/release.sh

# Create or update the GitHub pre-release v<version> (clean main only)
scripts/release.sh --publish

# Rewrite only the notes of the existing release v<version>, from its tag (nothing built)
scripts/release.sh --notes

# Preview the notes: <version> and <rev> default to Cargo.toml's and HEAD
scripts/release-notes.sh 0.2.0 origin/main

# Re-render the .dmg window background after changing assets/dmg/background.svg (needs Chrome)
scripts/dmg-background.sh

# Re-render the app icon (icon.png, icon.icns, the site's favicon) after changing assets/icon.svg (needs Chrome)
scripts/app-icon.sh
```

A release's notes are generated by `scripts/release-notes.sh`: a "What's new" section from the Conventional Commit subjects since the previous version's tag (`feat` under New, `fix` under Fixed, `perf` under Improved; other types and the `site` scope left out), between the intro line and the rest of `scripts/release-install.md` (install, first open, requirements). The app reads that section back, so keep its headings and each item's trailing `(#n)`.

The .dmg is laid out by `dmgbuild` (installed by `release.sh` in `target/dmgbuild`), from `scripts/dmg-settings.py`: the background, the window size and where the two icons sit.

## Architecture

- `main.rs`: arguments (`<repo>`, `--screenshot <png>`).
- `app.rs`: the state (`App`), the actions (`Cmd`, run once per frame by `App::run`) and the dialogs (`Dialog`). The views push `Cmd`s, never change the repository themselves.
- `app/views.rs` (toolbar, sidebar, history, details, diff, dialogs, keys), `app/palette.rs` (Cmd+K), `app/repos.rs` (Cmd+O), `app/project.rs` (the Project section), `app/board.rs` (the full-screen project board, Cmd+B; Esc closes its drawer then the board), `app/board_full.rs` (the full board, ⌃⌘B, #153: the board alone in the window under one thin bar with the repository, the branch, the views and Exit; the ticket in a drawer; Esc closes the drawer then leaves; switching tab or repository keeps it), `app/tab.rs` (one open repository's state), `app/tabs.rs` (opening, closing and switching tabs, the strip shown from two tabs, the tabs kept in `repos.json`), `app/assistant.rs` (Claude).
- `git.rs`, `worktree.rs`, `undo.rs`: Git through its command line. Every local action takes a `Snapshot` first, so Cmd+Z takes it back.
- `checkout.rs`: checking out a branch behind its upstream (`plan`): fast-forwarded at once when it is only behind, the Check out dialog when it has diverged; its actions, and the Git sequence run as one undo step (`run`), which the toast offers to take back with Cmd+Z.
- `operation.rs`: a merge, rebase, cherry-pick or revert stopped on conflicts (`Repo::in_progress`): Abort, Continue and Skip (`Repo::operation_step`). Each first copies the stopped operation (its files in the Git folder, the index with its conflicts, the files that differ from HEAD), so Undo puts it back whole, only when nothing changed since. `app/operation.rs` holds the banner over the history and the Abort confirmation.
- `push.rs`: the Push dialog's model (Push… ⇧⌘P and the palette): remote, remote branch, `--set-upstream` for a new one, Force push as `--force-with-lease` (asked twice when it replaces commits), Push all tags; its preview is `Preview::push`. The toolbar's Push stays direct (`Tab::push`).
- `delete.rs`: the Delete branch dialog's model (`Dialog::DeleteBranch`), from a local branch, a remote branch of the sidebar or a pill of the graph (right-click): the local branch and its remote branch as two check rows when both exist, the one clicked ticked. The local deletion is one Undo step (with its worktree); the remote one runs `git push <remote> --delete` in the background, asked twice since Cmd+Z can't take it back, and notes an open pull request that GitHub will close. A remote branch already gone only drops its stale ref.
- `menu.rs`: the macOS menu bar (Fourchette, File, Edit, View, Repository, Window, Help, laid out like the original's): a tested model of titles, shortcuts and greyed-out rules, and the AppKit menu. A pick is queued and turned into the `Cmd` of its button in `App::raw_input_hook` (Edit items go to the focused text field). `build.rs` links `assets/Info.plist` into the binary so the menu says "Fourchette" outside an .app bundle.
- `modal.rs`: the frame every dialog shares (#91): backdrop, centred card with shadow and 14 pt corners, header (icon tile, title, status line with branch pills, cross), body, footer (hint with keycaps, Cancel then the main action on the right, red when destructive), three widths, Enter and Esc, the scale-and-fade appearing. Also the choice cards, check rows, text fields and notes inside dialogs, and the card, backdrop and animation that Settings, the palette, the switcher and the toasts use. Call `ui::menu_rows` first in a context menu.
- `cockpit.rs`: the worktree cockpit (#26): each worktree's state (changes, ahead and behind, last commit), its branch's pull request (one `gh api graphql` query with an alias per branch) and whether Tidy up removes it (`verdict`: its pull request merged, squash included, or its branch in the base branch, and nothing uncommitted or unpushed). `tidy` removes the worktrees and their local branches, never a remote one; Undo puts them back. `app/cockpit.rs` holds its window, opened from the sidebar's Worktrees section and the palette, with the issue the branch name carries (`issue::linked_issue`).
- `titlebar.rs`: no title bar strip, like the original. The content fills the window, the toolbar is its top edge (dragging its empty background moves the window, a double-click zooms it), and on macOS the red, yellow and green buttons are moved onto the toolbar's centre line, with `INSET` left free for them; they are re-placed on the window's resize and full screen notifications as well as every frame, because AppKit puts them back at each resize step. `--screenshot` shows the egui content only, without those buttons.
- `repo_state.rs`: what the switcher shows of each repository of the list, read in background threads four at a time and kept: changes, ahead and behind (`git status --porcelain=v2 --branch`, read again after a minute), the open pull requests and those waiting for my review (one `gh api graphql` query for all of them, every 5 minutes; nothing without `gh`), and Fetch all (`git fetch --all --prune` in each, its failures listed with Git's message in the switcher and on the row).
- `home.rs`: the home page's model (issue #109): the repository list in sections (Favorites, Recent, the groups made by hand, one per GitHub organisation read from the remote, "Not on GitHub"), and the repositories of a section whose names share a first word proposed as a group. `app/home.rs` draws it in a tab without a repository (`Tab::home`): at launch when no tab is left to reopen, in a new tab (⌘T, "+") and with ⇧⌘O; the remotes are read in a background thread. Keep as a group writes the switcher's groups; Dismiss is kept in `repos.json` under `home`.
- `clone.rs`: cloning a repository (#204): the person's GitHub repositories and their organisations' (one `gh api graphql` query, the 100 most recently updated of each account, cloned in `gh`'s `git_protocol`), what the search field takes (a URL or `owner/name`), the destination check (a new or empty folder), whether a repository of the list already is that clone (`already_cloned`, from its remotes), and `git clone --progress` in a thread (`start`, in `LC_ALL=C`, with `gh` as an extra credential helper for GitHub over HTTPS), its stderr read into `Progress`; and `login`, `gh auth login --web` in a thread (without a terminal gh writes the one-time code and the page at once, copies the code itself and waits; Cancel kills it). `app/clone.rs` holds the dialog (home page, File › Clone Repository…, the palette): search, account pills, the list, "Clone into" with Change… (kept in `repos.json` under `clone`, `~/dev` by default), the progress and Git's error, and without `gh` signed in a Sign in to GitHub button (the code shown with Copy, the page opened, the list read again once signed in) or, without `gh`, `brew install gh` to copy; once cloned the repository joins the list and opens in the home page's tab (a new one otherwise), and one already in the list opens instead.
- `library.rs`: the repository list (`~/Library/Application Support/Fourchette/repos.json`): groups, favourites, last opened, the chosen GitHub project. `missing` lists the entries whose folder is gone (one on an external disk not mounted stays), which "Remove N missing" (home page and switcher) takes off with `remove`; its toast's Undo button (the list's, not Cmd+Z) runs `put_back`. A repository opened from a temporary folder (`is_temporary`) is neither added to the list nor kept in the tabs.
- `icon.rs`: the app icon (#159). Teal is the shipped `assets/icon.png`; another colour (Settings › Appearance › App icon: ten presets and a free colour in a picker, `IconColour` in `Settings`) is drawn in Rust with `tiny-skia` like `assets/icon.svg`, from a gradient derived in OKLCh from that one colour (`gradient`). `app/app_icon.rs` draws it in a background thread, gives it to the Dock through the viewport and, from an .app bundle, to the Finder (`NSWorkspace setIcon:forFile:options:`, nil for Teal); each launch writes it again, since an update replaces the bundle. The custom icon is an `Icon\r` file and a Finder flag at the bundle's root: the app still launches and `codesign --verify` passes, only `--strict` reports it.
- `city.rs`: the board's City view (#190, Board · List · City): the tickets the board's filters keep as an isometric city, one district per `zone:` label and one plot per ticket, built as far as its status goes (Backlog bare ground, Ready staked out, In progress foundations under a crane, In review half up, To test built with a flag, Done built; a Feature a tower with a floor per sub-issue, a Bug a workshop, the rest houses). Each district has its own style (#200, `Style`: the town, the Mediterranean, glass and steel, industry, and from round the world Japanese, Nordic, desert and Dutch), drawn from its zone's name and never the same as the block on its left or above; `app/city/styles.rs` (and `styles/world.rs` for the world's) draws three variants of each kind per style and its colours, picked from the ticket's seed (`stable_hash`), and the district's pavement and free tiles; the parks mix trees of every kind and colour. `app/city.rs` draws it with the painter: the cranes turn, each open pull request linked to a ticket is a lorry driving to its site in the colour of its checks, the first assignee works on the site; drag pans, pinch or ⌘-scroll zooms, double-click fits, a hover shows the ticket and a click opens its detail. It only reads.
- `meal.rs`, `app/meal.rs`, `app/court.rs`, `app/art.rs`: the Big eater skin (#212, Settings › Appearance › Skin and the palette, `Skin::Eater`): a food court and a daily menu, in memory only, from 0 at each launch. `meal.rs` (pure, tested): a commit +50 kcal, a push +250, a merge +400, Undo −50 (never below 0, and it breaks the combo), the third bite within a minute of the one before ×2, the fourth and next ×3 (`Meal::streak`, `combo_left`), an operation stopped on conflicts an indigestion that pauses it until the next bite (`Meal::sick`), the stops `STOPS` (Starter 500, Main 1,200, Cheese 1,800, Dessert 2,400) announced once each, the Golden Fork at 3,000. `App::take_strides` takes the tabs' `strides` once a frame and gives them to `course_strides` (Runner) or `meal_bites` (Big eater). `app/meal.rs`: the bar floating centred at the bottom of the central view like the course bar (`App::centre`; a layer painter, no click: the kcal on a track with the stops, the fork at the total and the last bites flying into it, the combo and its countdown, green while sick), the toolbar's "N kcal ×k" pill, the announcer's toasts (`Tone::Bite`, `Combo`, `Spit`, `Sick`, `Stop` through `coach_toast`) and the Golden Fork card with Second helping and Nap time (its header tile drawn with `Modal::icon_art`). `app/art.rs`: every icon and character of the skin, from the design canvas's Icons artboard as SVG paths rendered by the litter's `Pen` (`mess::path` reads M, L, H, V, Q, C, A and Z, absolute or relative): `FORK_GOLD` and `FORK_SILVER`, the simplified fork below 32 points (`fork_small`), the `GOLDEN_FORK` trophy, `BURGER`, `CHIPS`, `PIZZA`, the toasts' `cutlery` and the `EATER`. `app/court.rs` (and `court/dishes.rs`, iso dishes with the same ink outline, shade, highlight and face): `Tab::court_view`, drawn in place of the City view under the skin, whose switch then reads Food court, with the city's isometric painter (`city::layout_with` keeps a 4 × 4 block in the middle, `City::reserved`; `Tab::iso_view` pans and zooms): one restaurant per zone in its style's colour (striped awning, sign with its name), one dish per ticket (Backlog an order slip, Ready raw ingredients and a cook waiting, In progress on the grill in flames, In review under a cloche, To test tasted with a fork stuck in, Done served with a kawaii face; a Feature a burger with a layer per sub-issue, a Bug a chili with flies until done, the rest a pizza, donut or soda by seed), a delivery scooter per open pull request in the colour of its checks, and on the reserved block the big eater at his table facing the viewer (his big chair behind, a red and white cloth, the dishes served and a stack of plates, a bite of burger on his silver fork, pizza boxes on the floor).
- `snapshot.rs`, `share.rs`, `app/snapshot.rs`: the photo of the board's third view (#222, the city, or the stadium, mountain or food court of a skin) and its postcard (#223). The bar's camera draws the view fitted for a few frames (`board.city` set aside, no hover bubble while `board.shooting`, the caption in the corner, the skins' bars and litter hidden) and keeps it so until `ViewportCommand::Screenshot` hands back the window's image (the renderer takes the frame after the request), cropped to the view in Retina pixels and written as a PNG in the temporary folder. Then the system's shutter sound, a white flash and the photo shrinking into a thumbnail at the bottom right with Share… (`NSSharingServicePicker`: Mail, Messages, AirDrop, Slack…), Copy (PNG and TIFF on the pasteboard) and Save…; Esc or its cross closes it. The postcard asks for an audience, has Claude write the changelog of Unreleased and the latest release (`changelog::prompt` in a thread, Cancel drops it), takes the view's photo exactly as the camera does (without the caption) and composes a vintage postcard around it (#232), in paper colours that don't follow the theme, drawn over the window for two frames and photographed: "Greetings from" and the repository's name in retro letters in the paper above the photo (never over it), the changelog as its message in ink (`board::markdown_ink`), a perforated stamp with the fork, a dated postmark and the To / From address; the photo is then pasted back at its own resolution (`snapshot::paste`). Its menu chooses Card alone or On a table (the `postcard_table` setting): `snapshot::on_table` lays the card askew, with its shadow, on the skin's table (`Surface`: oak for the city, the track's tartan, the trail's gravel, the food court's gingham, the gaming room's lit desk mat), in a thread. It only reads.
- `app/view_tabs.rs`: the Changes · History · Project tabs above the history (they replaced the sidebar's first three entries): the active one is derived from the tab's state (`active_view`), Project is greyed with the reason when the repository has no GitHub project (`project_unavailable`). The board takes the centre under them; the sidebar and details panel stay.
- `app/issue.rs`: the issue of the current branch (the first number of its name that is an issue of the repository on the project): its chip in the toolbar, which opens its detail on the board, and the offer to move it, In progress after a checkout and In review once `gh pr list --head` finds its pull request. The move is the board's (`Tab::project_move`); Settings › Git can make it without asking, and its confirmation offers Undo, which moves the status back on the project (not Cmd+Z, which is Git's).
- `github.rs`: the GitHub project through `gh` in a background thread: the projects of the repository, then the project's items in the project's order through `gh api graphql` (types, labels, fields, sub-issues, linked pull requests), shared by the sidebar section and the board. A card dragged on the board or moved with "Move to" changes at once on screen; its Status and its position are then written (`updateProjectV2ItemFieldValue`, `updateProjectV2ItemPosition`) by one thread in order, and a refused write puts it back with the reason. ## New subjects

Every new subject (feature, improvement or bug fix) follows the `topic` skill, in `.claude/skills/topic/SKILL.md`, also run with `/topic`: analyse, find or define the GitHub issue with the dev, make a worktree (always, without asking), work, test (cargo test, clippy, screenshots), have the dev try it from their terminal, then commit, push, PR, move the issue on the project and tidy up. One subject per issue, worktree and PR. No code before the issue is defined.

## Work items (GitHub)

Work items are GitHub issues of `C2-POLY/fourchette`, tracked in the organisation's project **Fourchette** (<https://github.com/orgs/C2-POLY/projects/1>, number 1). `gh` must be signed in with the `project` scope (`gh auth refresh -s project`).

Issues are written in French and kept short:

- Title: `<Zone> : <ce qu'il apporte>`, for example `Sélecteur : ranger un dépôt dans un groupe`.
- Body: `**En tant que** …, **je veux** …, **afin de** …`, then `**Critères d'acceptation**` with 3 to 5 checkboxes, then `**Livré** : \`vX.Y.Z\`` once delivered.
- Type: the organisation's issue types, `Feature` (a capability, a parent issue when it is split), `Task` (an improvement, tooling, docs) or `Bug`. Split work is sub-issues; "B cannot start before A" is a `blocked by` relation, not a sentence.
- Labels: one `zone:` label (`zone:graphe`, `zone:historique`, `zone:barre-latérale`, `zone:sélecteur`, `zone:github`, `zone:assistant`, `zone:git`, `zone:annuler`, `zone:worktrees`, `zone:palette`, `zone:thème`, `zone:outillage`), and once delivered one version label (`v0.2.0`). Create a missing label rather than skipping it.
- Assignee: the person who did the work.
- Status on the project: `Backlog` (defined), `Ready` (ready to take), `In progress` (its worktree exists), `In review` (PR open), `To test` (merged, a criterion still untested by hand), `Done` (tested by the dev and merged).
- Every delivered change has an issue, including small ones only visible in `git log`.
- The PR closes its issue (`Closes #12` in its body).

## Versioning

- The version lives only in `app/Cargo.toml` (`version`), as `MAJOR.MINOR.PATCH`.
- One working day is one minor version (0.x while the app is not distributed). Bump it in the first commit of the day that changes something visible in the app, inside that commit. A day that only fixes bugs bumps the patch instead. Commits that only touch docs or tooling do not bump it.
- Never put the version number in a commit message.
- After each merge into `main`, move the current version's tag to `main`, then re-run `scripts/release.sh --publish` to update its pre-release. Tags only ever point at `main`:

```bash
git fetch --tags
git tag -f v0.1.0 origin/main && git push -f origin v0.1.0
```

- History: v0.1.0 is the work of 2026-11-04 (the rebuild, the repository switcher and the Project section).
